= BIDS Parsing & Dataset Normalization
:navtitle: BIDS Parsing & Dataset Normalization

[.lead]
This page traces the path from a BIDS directory on disk to the
`BidsDataset` in-memory model, describing `BidsParser`,
`LibBidsShWrapper`, and the model value objects.

image::generated/sequence-frombids.svg[fromBIDS sequence diagram]

== Overview

Parsing is a three-step pipeline:

. `LibBidsShWrapper` runs the external `libBIDSsh_parse_bids_to_csv` shell function
  and captures its CSV output.
. `BidsCsvParser` converts the CSV rows into `BidsFile` objects.
. `BidsParser` assembles the `BidsFile` list into a `BidsDataset`, then loads
  `participants.tsv` metadata.

== LibBidsShWrapper

`LibBidsShWrapper` bridges Groovy and Bash.  It resolves the libBIDS.sh script through
an ordered search:

. Embedded path inside the plugin installation JAR
  (`~/.nextflow/plugins/nf-bids-<version>/lib/libBIDS.sh`).
. Well-known relative paths (`lib/`, `libBIDS.sh/libBIDS.sh`, several `../` variants).
. System-wide installs (`/usr/local/bin/libBIDS.sh`, `~/.local/bin/libBIDS.sh`).
. Any custom path supplied via `options.libbids_sh`.

The final command is built as an array (never a concatenated string) to prevent shell
injection:

[source,bash]
----
bash -c 'set -euo pipefail && source "$1" && libBIDSsh_parse_bids_to_csv "$2" > "$3"' \
    bash <scriptPath> <bidsDir> <outputCsv>
----

Paths are validated against a character-allow-list before use; semicolons, pipes,
backticks, and other metacharacters raise `IllegalArgumentException`.

The wrapper exposes a `validateLibBidsScript(path)` convenience that confirms the file
exists, is readable, and contains the expected `libBIDSsh_parse_bids_to_csv` function
symbol.

=== Error surface

If libBIDS.sh is not found, `LibBidsShWrapper` throws `FileNotFoundException` with a
multi-line diagnostic listing all search paths and remediation steps (e.g.,
`git submodule update --init`).

== BidsParser

[source,groovy]
----
package nfneuro.plugin.parser

@Slf4j
@CompileStatic
class BidsParser {
    BidsParser(Session session) { ... }
    BidsDataset parseToDataset(String bidsDir, String libBidsShPath = null)
}
----

`parseToDataset` is the single public method.  It:

. Calls `LibBidsShWrapper.parseBidsToCSV(bidsDir, libBidsShPath)` to obtain a temp CSV.
. Passes the CSV file to `BidsCsvParser.parse()` to get a `List<BidsFile>`.
. Constructs a `BidsDataset(bidsDir)` and calls `dataset.addFile(file)` for each entry.
. Calls `dataset.loadParticipants()` to populate `dataset.participants` from
  `participants.tsv`.

After parsing, `BidsHandler` applies <<bidsignore,bidsignore filtering>> to the
returned file list before routing it to the set handlers.

== Bidsignore filtering

=== Overview

After the raw file list is produced by `BidsParser`, `BidsHandler.applyBidsIgnore`
filters out any `BidsFile` whose path matches a pattern listed in a bidsignore file.
The mechanism mirrors `.gitignore` conventions and is implemented by
`BidsIgnoreFilter`.

=== File resolution

The ignore file is resolved in this priority order:

. **Explicit override** — `options.bidsignore` path supplied to `Channel.fromBIDS()`.
. **Auto-detected** — `.bidsignore` at the BIDS dataset root (e.g.
  `/data/my_bids/.bidsignore`).

If neither source provides any patterns, no files are removed.

[NOTE]
When `options.bidsignore` is set, `BidsChannelFactory.preFlightChecks` validates
that the file exists and is readable before the pipeline starts.

=== File format

The bidsignore file contains one glob pattern per line.  Blank lines and lines
starting with `#` are silently ignored.

[source,text]
----
# ignore phantom subjects
sub-phantom/**

# ignore all JSON sidecars
**/*.json

# ignore a specific session
sub-01/ses-pilot/**
----

Supported glob syntax (via `java.nio.file.FileSystems`):

[cols="1,3", options="header"]
|===
| Pattern token | Meaning
| `*`           | Match any sequence of characters within a single path segment
| `**`          | Match any sequence of characters including path separators
| `?`           | Match exactly one character
| `[abc]`       | Match any character in the set
|===

Patterns are matched against the **path of each file relative to the BIDS dataset
root**, so `sub-99/**` correctly discards all files for subject 99 regardless of
the absolute location of the dataset on disk.

=== Usage example

[source,nextflow]
----
// Auto-detect .bidsignore from the dataset root
Channel.fromBIDS('/data/my_bids', 'bids2nf.yaml')

// Supply a custom ignore file
Channel.fromBIDS('/data/my_bids', 'bids2nf.yaml',
    [bidsignore: '/data/my_bids/custom.ignore'])
----

=== BidsIgnoreFilter class

[source,groovy]
----
class BidsIgnoreFilter {
    // construct from a list of raw patterns
    BidsIgnoreFilter(List<String> patterns, String bidsRoot)

    // factory: read from an explicit file path (returns empty filter if file absent)
    static BidsIgnoreFilter fromFile(String ignoreFilePath, String bidsRoot)

    // factory: auto-detect .bidsignore at the dataset root
    static BidsIgnoreFilter fromBidsRoot(String bidsRoot)

    // true when the file path matches at least one ignore pattern
    boolean shouldIgnore(String filePath)

    // true when no patterns were loaded (the filter is a no-op)
    boolean isEmpty()
}
----

== The model layer

=== BidsFile

`BidsFile` represents a single file entry as parsed from the libBIDS.sh CSV.  It
carries:

* `path` — relative path within the BIDS directory.
* `suffix` — BIDS suffix (e.g. `T1w`, `dwi`, `MESE`).
* `extension` — file extension (e.g. `.nii.gz`, `.json`).
* A map of BIDS entity key-value pairs (`subject`, `session`, `run`, `dir`, `echo`, …).

=== BidsEntity

`BidsEntity` is a named entity occurrence, such as `subject=sub-01` or `echo=1`.
`BidsEntityUtils.groupByEntities(files, loopOverEntities)` groups `BidsFile` lists
by the Cartesian combination of entity values named in `loop_over`.

=== BidsDataset

`BidsDataset` holds:

* `path` / `name` — root directory and dataset name (from `dataset_description.json`).
* `description` — parsed JSON dataset description.
* `files` — the full `List<BidsFile>`.
* `participants` — rows from `participants.tsv` as `List<Map<String,String>>`.

=== BidsChannelData

`BidsChannelData` is the internal carrier produced by set handlers before final channel
emission.  It wraps the grouped and resolved file references for one subject-session
combination, and is converted to the flat or legacy output map by `BidsHandler`.
